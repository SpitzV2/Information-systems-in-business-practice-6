# Принципиальные архитектурные решения

## 1. Линейная цепочка проверок по принципу Early Exit (ранний возврат)
Вместо глубокой вложенности блоков `if-else` логика метода `route()` оформлена через последовательные операторы раннего возврата `return`. Проверки отсортированы строго по убыванию критичности: `Персональные данные` -> `Высокий риск` -> `Лимит финансов` -> `Срочность` -> `Стандартный маршрут`. Это гарантирует соблюдение регламента безопасности и исключает перекрытие строгого правила более слабым.

## 2. Локализация финансового лимита в именованной константе
Пороговое значение 500 000 вынесено в `public static final long FINANCE_LIMIT`. Это устраняет "магические числа" в теле алгоритма и позволяет при изменении финансовых регламентов компании переконфигурировать порог согласования в одном месте.
