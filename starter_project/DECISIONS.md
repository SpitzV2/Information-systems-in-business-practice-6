# Принципиальные архитектурные решения

## 1. Выделение валидации и линейная цепочка Early Exit (ранний возврат)
Валидация входных данных декомпозирована в отдельный вспомогательный метод `validateInput()`, что защищает алгоритм от исключений `NullPointerException` и некорректных диапазонов, изолируя защитные проверки от бизнес-правил.
Основная логика метода `route()` оформлена через последовательные операторы раннего возврата `return` вместо вложенных блоков `if-else`.
Проверки бизнес-правил отсортированы строго по убыванию критичности:
`Персональные данные` -> `Высокий риск` -> `Лимит финансов` -> `Срочность` -> `Стандартный маршрут`.
Это гарантирует строгое соблюдение регламента безопасности и исключает случайное перекрытие строгого правила более слабым.

## 2. Локализация финансового лимита в именованной константе
Пороговое значение 500 000 вынесено в `public static final long FINANCE_LIMIT`.
Это устраняет «магические числа» в теле алгоритма и позволяет при изменении финансовых регламентов компании переконфигурировать порог согласования в одном месте без риска нарушения работоспособности остального кода.
